# meta-ads-campaign-cloner — סקיל לשכפול קמפיין מנצח עם וריאציות

> נבנה ע"י **Roey Treister** עבור הוורקשופ "Claude Code × פרסום במטא".
> כל הזכויות שמורות — ראה [LICENSE](../LICENSE).

זה הסקיל השני שקיבלת בוורקשופ. הוא מתמחה בתרחיש ספציפי וחזק: יש לך קמפיין שעובד טוב, ואתה רוצה לבנות ממנו קמפיין חדש עם שינויים מבוקרים — קריאייטיב חדש, קופי חדש, תאריך חדש, או שילוב.

---

## למה צריך סקיל ייעודי לזה?

הסקיל הראשי `meta-ads` יכול לבנות קמפיין מאפס לפי spec JSON — אבל הוא דורש ממך להגדיר את ה-spec הזה במלואו. שכפול קמפיין מהאפס בכל פעם זה עבודה מיותרת.

הסקיל הזה מבצע את התהליך הנכון:
1. **קורא** את מבנה הקמפיין הקיים שלך (כל המודעות, הקופי, ה-targeting, ה-pixel)
2. **שומר** עליו במלואו — אין סיכוי ש-Claude "שכח" משהו או "המציא" משהו
3. **מחיל** רק את השינויים שביקשת — קריאייטיב חדש, קופי חדש, תאריך חדש
4. **מציג** לך תכנית מלאה לאישור לפני שהוא יוצר משהו במטא
5. **רץ** רק אחרי שאמרת "בצע"

---

## תלות בסקיל הראשי

הסקיל הזה **משתמש בסקיל `meta-ads`** — שני הסקילים חולקים את `accounts.json`, את הטוקנים, ואת חלק מה-scripts.

**לפני שתתחיל לעבוד עם `meta-ads-campaign-cloner`**:
- ודא שהסקיל הראשי `meta-ads` מותקן ועובד
- ודא ש-`auth_check.py` מחזיר `ok: true`
- ודא שאתה יכול להוציא דוח בסיסי מהסקיל הראשי

אחרת — הסקיל הזה יכשל בשלב הראשון.

## ה-flow של הסקיל בפועל

הסקיל לא יוצר שום דבר במטא לפני שאתה אומר "בצע". התהליך:

1. **Phase 1 — הבנה.** Claude שואל אותך מה צריך לדעת (איזה חשבון, איזה קמפיין מקור, מה השינויים).
2. **Phase 2 — קריאה.** הוא מריץ `fetch_structure.py` ומשיג את כל הקמפיין המקור.
3. **Phase 3 — תכנון.** הוא בונה spec JSON שמייצג בדיוק מה ייווצר.
4. **Phase 4 — אישור.** הוא מציג לך סיכום מסודר של התכנית. אתה מאשר ב"בצע".
5. **Phase 5 — ביצוע.** הוא מריץ `run_clone.py` והקמפיין החדש נוצר ב-Ads Manager — הכל PAUSED.

אם משהו נופל ב-phase 5 (נדיר אבל קורה — האינטרנט נחתך, מטא מחזיר שגיאה לאחת המודעות) — נשמר state file שמראה מה כבר נוצר. אפשר להמשיך מאיפה שעצרנו, לא לבנות הכל מחדש.

---

## מה להחליף ב-spec_example.json

הקובץ `spec_example.json` הוא תבנית — לא דוגמה אמיתית. כל ה-IDs בו (`act_0000...`, `0000000000000000` וכו') הם placeholder. אל תשתמש בו ישירות.

ב-flow רגיל **אתה לא תיגע בקובץ הזה**. Claude יבנה את ה-spec בעצמו על בסיס הקמפיין המקור שלך. הקובץ נמצא שם רק כהפניה ראויה למתי שתרצה להבין מבנה.

---

## ⚠️ כללי בטיחות

- **הכל נוצר PAUSED.** הסקיל לא יוצר קמפיינים פעילים. אתה מחליט מתי להפעיל מ-Ads Manager אחרי שראית שהכל נראה טוב.
- **אישור מפורש לפני ביצוע.** לא יספיק "OK" או "אישור" — צריך לכתוב **בצע** במפורש.
- **עוקבים אחרי המקור 1:1.** אם הקמפיין המקור היה עם pixel ספציפי, conversion event ספציפי, page_id ספציפי — הסקיל מעתיק אותם בדיוק. הוא לא מנחש.
- **שינויים רק לפי בקשה מפורשת.** אם ביקשת "החלף תאריך 19.4 ל-4.5" — הוא יחליף רק את זה. הוא לא יחליף "תאריך" באוויר ולא יערוך טקסט שלא ביקשת.

## פתרון בעיות

אם משהו לא עובד:

1. **`fetch_structure.py` נכשל** — הטוקן או ה-account_id לא נכונים. תריץ קודם `auth_check.py` מהסקיל הראשי.
2. **`run_clone.py` נכשל באמצע** — קרא את ה-state JSON שנכתב. הוא מראה איזה אובייקטים כבר נוצרו. תיקון נפוץ: pixel_id לא תואם ל-account_id, תמונה חסרה ב-image_dir, או page_id לא נגיש לחשבון.
3. **תווים בעברית מוצגים מוזר** — תוודא שהגדרת `PYTHONIOENCODING=utf-8`. ב-Windows cmd.exe יש מקרים שצריך גם `chcp 65001` לפני הרצה.

עוד פרטים: `references/spec_format.md` — שם מתואר כל שדה בפירוט, כולל ה-CBO/Ad Set budget logic ואיך עובד `copy_substitutions`.

## נשאר עוד שאלה?

הסקיל הזה תוכנן לתרחיש שכפול. **למשימות שונות** — תחזור לסקיל הראשי `meta-ads`. הוא בנוי כללי יותר ויודע גם דברים שהסקיל הזה לא יודע (ניתוחי fatigue, שינוי תקציב על קמפיין קיים, וכו').
